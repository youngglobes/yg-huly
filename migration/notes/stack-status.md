## Everyday commands (run from `huly-selfhost/`)
```bash
docker compose ps                 # status
docker compose logs -f front      # tail a service
docker compose up -d              # start / re-create
docker compose down               # stop (keeps volumes/data)
docker compose down -v            # stop AND WIPE all data volumes (destructive)
```

When the backup arrives:
1. Drop it in `../backup/`, unzip to `../backup/extracted/`.
2. Run (fill in real values):
   ```bash
   cd huly-selfhost
   ./restore-workspace.sh ../backup/extracted <WORKSPACE_SLUG> -e <ADMIN_EMAIL> -p <ADMIN_PASSWORD>
   ```
   Same source/target version → the built-in `--upgrade` is a harmless no-op.
3. ⚠️ **Blob/attachment caveat:** Huly cloud uses a *datalake* blob store. If the backup contains `blobs/blobs.json`, file attachments/images are NOT uploaded into this minio-based stack (the script warns and skips them). DB content (projects, issues, docs, comments, time entries) restores fully. Decide separately how to migrate large files.
